# Fixed gateway capability boundaries

Default mode tests the compiled original owner in an ordinary process:
exact SID/attributes on root and console members, original zero-capability
policy refusal of the singleton, LPAC enforcement, ordinary caller refusal
before private state, and actual own-token refusal of the new worker entry.
It also checks bounded endpoint/content envelopes, actor/time binding,
inconsistent phases, unknown fields, and refusal to claim HTTPS completion
after content was returned. No profile/Job/WFP/protected process, socket or
network connection is created by these default tests.

`host-reference` separately invokes the same three read-only IP Helper calls
used by the comparison canaries. It emits real adapter and TCP-table contents
for trusted local research; capture it only in the ignored evidence task.
It does not start a protected process, modify policies or connect anywhere.
This ordinary positive reference is not a restricted privacy result.

Only distinct compiled Broker qualification commands select the new zero/singleton
comparison workers. The native profile assignment remains unexecuted until a
new fixed installation/experiment is specifically approved. Their endpoint
probe creates and closes one unbound socket, then attempts real content reads
regardless of endpoint failure. Only three explicit access-denied results and
a proved closed endpoint allow the fixed HTTPS step. Everything else closes
through the original owner and retains the result for analysis. Three denied
APIs do not establish complete L3 privacy acceptance.

`Endpoint.Created` means the fixed creator returned an adopted managed socket.
False alone does not uniquely prove the raw OS create failed: adoption/setup
can also fail. Native socket/NT error context, phase and nullable owned-handle
closure remain separate; an unconfirmed endpoint cannot pass the gate.
