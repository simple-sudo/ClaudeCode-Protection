# 保护链工程整理与回归边界

## 职责与依赖

| 部件 | 拥有的决策 | 应随之验证的调用链 |
| --- | --- | --- |
| ProtectionCenter、日常 ClaudeProtection | 普通用户交互、明确选择的工作区输入、安装同级文件预检查、结果读取 | 两个前端构建、普通 IPC、结果展示和取消 |
| ProtectionBroker、InstalledBroker | 固定命令分派、验证已安装宿主及当前版本、按操作应用未完成事务门 | Broker、Bootstrap、普通调用方拒绝、精确前驱和恢复 |
| ProtectedSession、ProtectionRuntimeLease | 原会话持有资格、资源和 Job，监督执行、撤销准入、隔离及停止 | 固定网关、离线工具、Job 和恢复边界 |
| AtomicAdmission、OwnedToolLaunch | 首指令前原子绑定进程、LPAC 和 Job，核对令牌、镜像及受限继承句柄 | LPAC 身份、能力、命令和句柄回归 |
| SessionResources、HostPrivacyProbe | 持有工作区和工具资源，收集并封存由原 owner 绑定的隐私观察 | 工作区 v3/v5/v6、三角色报告、工具释放与失败回执 |
| ProtectedLifecycleCoordinator | 编排用户意图和有限状态转换。原生 owner 适配仍待接入 | 过期、乱序、代理故障与关闭夹具，以及未来实际启停验证 |
| ProtectionBootstrap、ProtectionLifecycle | 固定工件安装、版本选择和受保护恢复；生命周期及恢复 JSON 是内嵌的显式协议 | 管理程序集、内嵌字节、版本兼容和原 owner 日志 |

## 本轮改动

- 隐私目录用不可变条目定义回报角色、目标类别、对象和最小权限。可信 owner
  由对象推导路径，受限 actor 按类别核对目标和 PID，再尝试固定的一项权限。
  编译器目录由 owner 进程、控制文件和已持有的根进程派生。历史 v5 摘要、33/28
  项顺序、回报形状和唯一允许 owner 确认缺失的设置目标用回归固定。
- 网关资格从可自由组合的布尔参数收敛为七个固定模式。Winsock 租约范围、
  LPAC 能力、内容采集和子命令由同一模式选择。Broker 对单参数命令显式分派，
  未识别的命令进入用法提示；quarantine 有独立分支。InstalledBroker 共享版本
  验证，操作特有的未完成事务和系统资格检查仍由原调用链施加。
- 资源准备和正常退出都尝试释放全部持有对象，保留最初的准备错误及释放错误。
  释放仍在原会话关停流程内，日志恢复资格仍取决于原 owner、Job 和关闭回报。
- 安装、恢复和普通前端共用 v1 资产目录。九个提权前需持有并校验的资产逐项
  标注；普通客户端校验完整清单身份，仍只打开这九个既有资产。共用目录页
  解析器和普通安装客户端归入 Shared。保留源码白名单，未引入部署 DLL 依赖。
- 将依赖 Windows 身份的恢复日志夹具独立成 Windows 测试。跨平台冒烟只跑纯
  策略和内存传输，普通编辑夹具显式声明所需管理程序集。构建触发覆盖内嵌样例。

## 接下来按功能推进

- 新增宿主检测项先定义对象、最小权限、正负对照及适用 actor。对协议身份有
  影响时，明确新旧格式的读写支持和范围，保留旧回报与冻结证据。
- 新增可执行工具需分别审核固定资产、工作区契约、最小环境、预执行身份
  和后代监督。原子创建边界不能由启动后补挂 Job 或普通进程测试代替。
- Bootstrap 与 Broker 共用管理库。先保持旧安装和恢复可读，再按实际产品
  功能推进内部边界拆分。外部发布布局、私有状态、安装及系统规则需要各自验证。
- ProtectedLifecycle 的下一步是接入原 owner 的可信适配器，复用已有准入和关闭
  证明。假 owner 测试用于验证状态转换及顺序，真实 GUI、全机 IPv6 和代理故障
  需要各自的原生证据。

第一轮官方 CLI 的边界见[离线资格合同](OFFICIAL-CLAUDE-OFFLINE-QUALIFICATION.md)。
