# 生成物保留与清理

适用范围仅为开发 checkout 的普通生成物。本规则不改变产品安装、恢复、安全策略或实验授权。
历史路径按 MIGRATION-20261031.md 只读映射；历史清单、哈希、原始日志及失败记录不改写。

| 类别 | 当前例子 | 处理规则 |
| --- | --- | --- |
| 必要证据 | 冻结输入/脚本/清单、原始日志、失败/取消/UNKNOWN、结果包、交付、转储和对应符号 | 默认保留原位置和字节；不能仅因旧、重复或 Git 忽略而删除 |
| 安装与恢复资产 | ApprovedPackage、对应 payload/stage、Bootstrap、控制计划、回执、原始 state/备份；系统安装目录及外部固定工具链 | 保留；普通生成物治理不读取私有安装状态、不调用产品或恢复入口，不修改安装资产 |
| 第三方工具缓存 | WinDbg 下载包和提取工具、PowerShell 下载包和运行时、调试符号 | 保留来源、版本、SHA256和所需离线副本；普通缓存不因此成为可信安装资产。仅对精确验证、能离线逐字节恢复的额外副本去重 |
| 可重建临时产物 | 新建任务中明确标记的 scratch、未被证据/冻结输入/恢复链引用的中间文件 | 任务结束时按精确清单处理；没有明确归属、依赖或恢复依据就保留。历史 bin/obj 也不自动视为临时目录 |

## 今后的最小规则

1. 每个任务只建一个 `work/<用途>-<日期>-<序号>` 主目录。在该目录的简短 README
   记录用途、结论、证据/输入/输出位置和临时文件清单；需要冻结的控制仍使用原有严格清单。
   失败重试作为同一任务的独立子记录保存，不覆盖原失败，也不复制整套工具或重跑已通过实验。
2. 新第三方缓存放在 `work/tool-cache/<工具>/<版本>`，记录下载来源及SHA256，任务只引用它。
   下载或解压前先查已有精确版本；不自动下载、不覆盖已有不同字节。历史缓存无需搬迁。
3. 新临时输出集中在任务内 `scratch/`，创建时列明可丢弃文件及重建方法。
   未标记的旧目录默认是证据。清理前排除冻结输入、安装/恢复依赖、链接和不明权限对象；
   不按目录名/扩展名/年龄批量删除，不跟随重解析点，不改ACL来读取或删除测试拒读样本。
4. 阶段结束做一次目录大小检查即可。`work` 超过4 GiB或本阶段增加1 GiB时列出最大的
   几项，决定是否在该阶段顺手处理；这些是复查提示，不是配额、删除条件或长期研发任务。
5. 真正删除前记录精确相对路径、大小、SHA256、保留副本/离线恢复方法和依赖判断。
   先验证恢复，再删精确文件并写实际结果。归档不等于释放空间；逻辑字节不等于磁盘实际回收。
   归档含敏感数据时沿用原隐私边界，不上传云端。治理结果不能授予任何旧冻结操作新的执行权限。

只读检查（PowerShell 7；不运行产品、读取文件内容或写入报告文件）：

```powershell
./scripts/Measure-WorkArtifacts.ps1
```

`-IncludeFiles` 可附加逐文件大小和修改时间；报告含本机相对路径，留在本地。
报告跳过链接并显式记录枚举失败；它不是对抗并发恶意替换的安全扫描器或清理授权。
没有自动删除、定时清理或新的通用执行器。
