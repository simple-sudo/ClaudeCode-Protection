# 可信自我安全评估与泄露指纹画像评估：设计与验收合同

状态：REQUIREMENT_ONLY / DESIGN（2026-11-03）；**未实现、未构建、未安装、未在真实 Claude Code 受保护身份中验收**。这是一份安全设计合同，不是授权执行脚本或新的安全准入凭据。

正式优先级与交付术语见[SECURITY-REQUIREMENTS](SECURITY-REQUIREMENTS.md)；现行安装、暂停、授权只见[CURRENT-STATE](CURRENT-STATE.md)；工作包与实际验收登记分别见[HOST-PRIVACY-AUDIT-DIRECTION-20261102](HOST-PRIVACY-AUDIT-DIRECTION-20261102.md)和[PROJECT-ACCEPTANCE](PROJECT-ACCEPTANCE.md)。沿用已有安装、Broker、ProtectedSession、LPAC/Job/WFP、网关、Watchdog、原 owner 及恢复链，不另建平行的通用执行器。

## 1. 两个系统与三个不同的结论

- **ASSURANCE-SELF（自我安全评估）**：从受信任管理侧验证保护组件及其实际强制边界，检查受保护 Claude 和完整派生执行链在明确授权范围内能、不能访问什么；同时记录授权编程/Git/网络/GPU 能否正常工作。评估保护是否有效，不等同于 GUI 显示运行中或检查某条规则存在。
- **ASSURANCE-PROFILE（泄露指纹与画像重建）**：只根据经证实在指定受保护身份下可见的字段，确定性关联其可能揭示的宿主网络、设备唯一性、位置、远控关联、长期状态和用户环境。既登记单点直接泄露，也登记组合推断与替代来源。
- **运行准入与保护动作**：现行可信 owner 按独立策略和实时门禁作出允许/阻断/保持隔离决定。评估报告自身不得启动、授权、提升、停止或修复会话；不能把评估“通过”直接转换成运行许可证。

目标是“评估—识别缺口—提出有界保护变更—取得适用授权—通过原机制实现—复测”，不是让 Claude 自己评估自己，也不是让保护进程自动拥有任意宿主管理权。

## 2. 信任域、数据流与自我保护

| 域 | 允许的数据与角色 | 绝对边界 |
| --- | --- | --- |
| 可信宿主管理/评估域 | 固定策略、资源目标目录、受限探测计划、脱敏证据、独立正控制、必要原始参考 | 仅可信 owner/明确授权维护者使用；保护策略、规则、源码、私有报告、管理 IPC、凭据不向 Claude 暴露 |
| 受保护执行域 | Claude Code CLI、经纳入的 hooks/MCP/PowerShell/Python/Git/编译器、最小授权项目和工具 | 不能读评估内部目录/管理接口，不能选择任意宿主目标、读取评估基准、改规则或签发 PASS |
| 证据交换边界 | 固定 schema、已绑定会话/安装/版本/输入/进程身份的有界结果 | 仅返回角色、操作、状态、必要错误码、时间及不含秘密的证据摘要；不透传原始配置、IP、MAC、UUID、Token 或私人路径 |
| 可信维护者 | 经权限核实的普通检查与必要 UAC 维护 | 高影响变更须预先核对对象、影响、时间、停止和恢复；不能为省事提供受保护进程可调用的通用提权 shell |

自我评估不能只相信被测子进程自报的 PASS。可信 owner 必须以持有的真实 token/Job/创建时间、资源对象、策略版本与阶段进行独立验证；执行前封存、结果签收和结束后的归属检查复用现有原语。哈希只能证明指定字节一致性，不能替代身份、ACL、所有权及运行期真实性。将管理员 PowerShell 的宿主观察与实际 LPAC/派生进程的访问结果严格分开。

评估系统运行与部署应位于可信保护边界之外，不把源代码、评估规则、基准数据、内部日志、管理协议、具名端点或真实秘密复制进普通 Claude 工作区、MCP 工具上下文或结果导出。即使 Claude 识别保护系统存在，P0 权限约束仍须成立；P1 中性命名与 P2 混淆不能替代强制隔离。

## 3. 自我安全评估：可执行要求

1. **计划与基线**：维护版本化的“信息目标→候选来源/API→实际对象及所需权限→授权可见性→必须拒绝的操作→正常功能”矩阵。至少含物理 IP/IPv6/MAC/BSSID、路由/DNS/连接、FlClash 代理配置和本地管理接口、UU 进程/网络端点/日志、设备唯一标识、GitHub/Codex/Claude 凭据、保护源码/控制面、跨会话状态。
2. **三方对照**：可信宿主可达性/对象身份正控制、同一真实受保护身份的最小越权负控制、同身份的合法功能正控制必须成对、同版本记录；不得为了取得证据预先读取真实秘密。正控制不可得时记 UNKNOWN，不把“目标缺失”冒充拒绝。
3. **完整执行链**：主进程及派生 PowerShell、Python、Git、Node.js、编译器、Hooks/MCP 等只对确实纳入的链路报告结论；新工具/高权限子进程、IPC、句柄继承、服务代理、管理接口、COM/CIM/WMI、驱动和设备 API 是独立候选来源。不能凭 EXE 名、过滤一个字符串或少数文件 DACL 证明整类信息不可见。
4. **网络双轨**：区分“读取本机网络状态/9090 管理数据”和“建立 TCP/UDP/DNS/IPv6 未授权连接”。美国授权出口的外部可见性与中国网络关联端点、物理网卡、内部节点信息分开判断；本地回环不自动可信。代理断开、Watchdog 漂移、owner 异常和重启恢复分别验证 fail-closed，不得依赖事后轮询弥补已放行窗口。
5. **设备能力与个体身份**：保留真实 NVIDIA/CUDA/PyTorch、必要计算及性能信息；对 GPU UUID、主板/BIOS/磁盘序列号、MachineGuid、MAC 等按接口验证。某接口实际无法隔离时记录剩余风险，不能以关闭 GPU、假值或命令输出替换声称已保护。
6. **报告与差异**：输出每一项目标的 ALLOW_AUTHORIZED / DENIED_CONFIRMED / EXPOSED / UNKNOWN / NOT_RUN / NOT_APPLICABLE（仅有明确场景依据）及失败原因、身份/版本/时间/对照/原 owner 证据；比较上次同范围记录，但绝不把历史 PASS 自动转授给新工件。

最小探测仅申请完成“能否打开/可否访问”所需权限，必要时采用非秘密自身控制对象和脱敏的存在性/连通性结果。需要更深入的实际敏感读数、真实网络探测、权限更改或故障注入时，必须先给出具体审查单并取得适用的人类决定；不自动运行或扩大到全盘扫描。

## 4. 画像重建：不依赖 AI 的确定性推理

**不使用本地/云端 LLM、远端画像 API 或把原始指纹上传到外部**。第一版采用版本化规则、信息目标目录、来源关联图和可重放的纯本地推断；规则输入为 owner 已验证的可见字段类别及脱敏属性，而非“宿主真实拥有但未证明 Claude 能读”的数据。

每条证据最少记录：source_id、信息目标、实际来源/接口、观察者身份与任务链、对象/权限、结果类别、时间有效期、规则版本、可信对照、是否独立来源、允许用途和脱敏证据引用。同一文件经多个命令读取只算同源，不得制造独立佐证。归属、时效、来源身份不明为 UNKNOWN；不允许画像引擎自称完成 Windows 权限证明。

画像结论分三级：

| 结论 | 语义 | 示例 |
| --- | --- | --- |
| CONFIRMED_DIRECT（直接证实） | 可见字段直接载明某一事实且来源可信 | 可直接读取含运营商 ASN 的外联元数据；只能确认该远端网络归属，不自动确认家宽运营商 |
| INFERRED_WITH_BASIS（有依据的推断） | 多个有来源的证据经公开确定性规则支持某个概率性关系 | 独立语言/网络/远控线索共同提示可能的地区或设备关联 |
| UNKNOWN / INSUFFICIENT（未知/不足） | 观测缺失、来源不独立、解释歧义或规则不适用 | 单凭美国代理出口、时区、昵称、SSID 或某个远程服务器 IP 不能确认真人位置 |

输出应同时给出“可观察到什么、依据哪些来源、只能推断什么、竞争性解释、无法确认什么、如何阻断”，严格分离真实事实、推断、UNKNOWN。不能把“已暴露 60%”作为可测量的画像完整度或安全阈值；信息件数、拒绝次数或平均分不能抵消单个关键 P0 泄露。若需展示覆盖率，只计算明确版本化目标矩阵中已测/未测的比例，并注明它不是身份识别概率。

**P0 一票阻断语义**：未授权的真实物理网络身份、FlClash/UU 敏感控制和连接细节、硬件唯一身份，以及中国电信/联通/移动或其他中国关联网络线索一旦经同一受保护身份证实可见，均触发相应 P0-HOST 缺口/发布阻断，哪怕 IP 属于第三方远控中继而非家庭或移动运营商。仅“猜测可能存在中国关联”的不确定线索不伪装为已证实泄露，应记录 UNKNOWN 并对必需资格保持 fail-closed。允许的美国代理出口不等于宿主位于美国，也不意味着代理配置对 Claude 可读。

画像报告不追求无依据地“还原真实用户”。授权项目源码、公开服务端看到的代理 IP、服务端跨账户关联与普通统计指纹可能仍产生不可消除的推断；评估要记录这些无法由本机隔离完全控制的残余风险，而不是承诺绝对匿名。

## 5. 风险策略、阻断和受控修复

- 风险是**按信息目标与最高严重度决策**，不是累加/平均分：P0_CONFIRMED_EXPOSURE → 对受影响的新准入阻断、现有会话按原故障机制维持隔离/安全终止；P0_REQUIRED_UNKNOWN / 证据过期 / 评估组件不可用 → 不得凭旧报告放行；证据不足只记 UNKNOWN，不虚构“泄露已发生”。
- 可信策略 owner 根据已有网络/生命周期/访问控制门作决定；画像引擎与普通 GUI 都没有授权权。评估是保护体系的一环，但不能以一个尚未实现的评估模块取代现有强制门；没有新评估资格的当前产品仍不得进入正式会话。
- 修复优先级：实际 OS 权限拒绝 → 合法功能的最小授权 → 原可信 Broker/网关有限接口 → 经论证的局部最小化/非敏感替代标识。不要用字符串过滤、假连接表、无效 hook 或隐藏服务名当作硬边界。
- 自动化可**提出修复候选和所需最小回归测试**，但不能绕过 UAC、冻结工件、版本门禁、失败恢复与用户批准来自动修改系统 ACL、FlClash/UU、网络或驱动；不无限循环重试。修复后在新版本/同范围重新取证，原 FAIL 与 UNKNOWN 仍可追溯。
- 运行中应由原可信持续监督链检测策略漂移、可见性变化和保护组件失效。周期性检查不是唯一边界；持续安全须由独立有效的 OS 强制限制和 fail-closed 实现保证。

## 6. 最小报告合同（拟议，非已实现接口）

| 字段 | 目的 |
| --- | --- |
| policy_version / rule_version / scope | 明确版本与信息目标、授权场景 |
| installation / session / owner / actor / job_binding | 防止别的身份和旧任务报告冒充本次结果；标识可为脱敏摘要 |
| probe_id / resource_role / access_kind / source_class | 固定探测计划与信息来源，不含真实私人路径 |
| outcome / native_error / control_outcome / observed_at / expires_at | 区分真实拒绝、可读、未知、时效和正控制 |
| correlation_rule / input_evidence_refs / independence / interpretation | 可重复的关联推断与非独立证据标记 |
| highest_severity / gate_recommendation / residual_risk | P0 不被均分稀释，最终决策仍由可信 owner 负责 |
| non_secret_artifact_digest / provenance / owner_seal | 绑定输出与原 owner 的可信来源，不把摘要本身当身份鉴权 |

公开/普通 GUI 应默认仅显示对象类别、风险级别、验证状态、可执行建议与必要的脱敏证据标识。可信完整报告仍是敏感资源，禁止自动上传、导出进 Claude 可读项目或在 GitHub/CI 中存放原始宿主字段。固定规则和版本可审查、可追溯；实现时需有针对输出泄露、报告伪造、回滚、访问越权的负向测试。

## 7. 建议的开发次序与完成标准

1. **合同与目标目录（本次）**：先确定两系统的身份/证据边界、状态/画像语义及 P0 判定；对应工作包仅 REQUIREMENT_ONLY / DESIGN。本次不修改可执行代码。
2. **有限自评 MVP**：沿原 owner 将已有非秘密资源拒绝、正控制和授权开发结果按新合同映射，新增极少量针对“实际阻断”的路径验证；禁止把现有 14 资源角色和 14 项环境准入混为一谈。
3. **画像规则 MVP**：在纯合成、无真实秘密的数据集上验证单点/跨来源/歧义/同源重复、美国出口、中国关联中继、UNKNOWN 和 P0 一票阻断。纯规则通过仅是普通组件 VERIFIED，不是实机防泄露通过。
4. **可信集成与正常开发**：让原 Broker/ProtectedSession/工具/网关/Watchdog 采集且封存实际受限身份证据；在同一 scope 下同时验证合法修改/编译/测试、Git/依赖、必要网络与 GPU。新权能先审查，旧合格样本在原 scope 内复用，不得无止境扩展探针清单拖延可用产品。
5. **正式验收**：按确切版本、身份、父/派生链、对象、权限与时效验证宿主/控制面不可访问、跨源无法重建 P0 敏感身份、故障时仍 fail-closed；仅在真实受保护 Claude CLI 主链及全体必需项通过后才可能 PRODUCT_DELIVERY_ACCEPTED。

明确不在本次完成的事项：代码实现、原生 LPAC/Claude 探测、真实秘密取样、画像准确率验证、网络/权限更改、安装、系统故障注入及正式会话授权。后续每轮交付须说明实际可用能力、受限证据、未测或失败项以及下一真实阻断，而不是只增加规则或报告数量。
