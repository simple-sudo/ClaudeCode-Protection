## 版本事实和切换

暂存完成14个固定组件的同句柄核验复制后，才在管理员状态中发布 `release-<release>.json`。它绑定安装ID、release、审查清单摘要和暂存操作ID。公开可读的 version.json 不作为包授权根。历史版本的 manifest 必须匹配管理员记录，严格字段和固定资产范围保持；不会因当前发布 pin 改变就遗失先前拥有版本的验证依据。

VerifiedVersion.Open 仅打开已有固定路径，不创建目录。它核对代码根/版本 marker 与管理员记录、manifest 摘要、固定目录的精确子项集合、每个文件的长度/哈希、owner/DACL、重解析/硬链接及最终路径。核验后的目录和所有payload文件句柄持有到切换完成，不接受多余 DLL、脚本或目录。只有私有构造得到的核验租约可以进入切换方法。

VersionLifecycle.InstallOrUpdate 已写具体源码调用：冻结计划→暂存并发布拥有记录→阶段回执→再核验全部payload→原子替换管理员 current.json→回读→记录完成。更新保留旧版本，不覆盖它。Rollback 只接受另一个曾被本安装选择的拥有版本，先重新核验它，并保留当前旧版本。

所有切换只能从 verified 阶段发生，runtime lease 必须保持 admission 关闭和所属进程为零。current.json 固定 Activation=INACTIVE，并绑定本次操作ID。选择历史记录绑定 release、manifest、操作ID和指针摘要，回滚不能把仅暂存但从未选择的版本冒充历史选择。

上述 runtime lease 仍只有接口，实际生产 broker/Job/WFP owner 尚未实现；不能把这些方法计作可运行安装版。当前批准包 pin 仍为 null，无新增入口或环境开关。

## 中断计划和账本

新计划在任何暂存/切换前保存原 current.json 的精确字节快照（base64）与 SHA-256；这个文件仅含版本元数据，不是认证资料。安装要求原指针不存在，更新/回滚要求原指针存在。旧计划缺少这些字段时拒绝，不补写历史。

LifecycleJournal.Read 从受保护管理员状态读取计划、每个连续编号账本和证明文件，检查严格字段、安装/操作/目标ID、序号、前序哈希、UTC格式、允许的阶段边、证明种类和摘要。stage/verify证明绑定该目标manifest，switch/finish证明绑定该操作的选择记录摘要；不能借另一版本的PASS。缺失、间隙、重复/外来字段或错误证明均失败。

只写计划尚未写首条账本的中断可识别为 recordCount=0，不能当完成；不能据此接受已切换目标。孤立证明、部分payload和原失败日志保留，不填补成旧时刻通过。

## 恢复的当前范围

实际嵌入 RecoveryProtocol.json 默认 REFUSE；只覆盖 install/update/rollback。它要求当前 runtime 无所属进程且 admission 关闭，保留原账本，禁止恢复过程改指针或网络。

| 当前指针事实 | 当前payload事实 | 对未完成操作的处理 |
|---|---|---|
| 本操作ID与目标release精确匹配 | 重新核验通过 | 记录当前未激活目标已核验；补齐缺失的选择记录；原账本不改写 |
| 与计划原指针的精确摘要相同 | 重新核验旧版本通过 | 中止未提交操作，保留原指针和暂存payload，不宣称已删除或安装完成 |
| 安装前后都没有指针 | 无当前payload | 记录未提交中止，保留部分payload与失败证据 |
| 其他操作指针、漂移、不可读、缺少必要拥有记录 | 未验证 | 拒绝推进，记录失败/UNKNOWN，不能自动恢复旧指针 |

已完成账本也不能代替当前资格：只有当前仍精确指向同一操作目标且payload重新核验通过，才记录当前观察；当前为旧值、缺失或外来值都拒绝。所谓“恢复”记录是新时刻事实，不倒填原阶段PASS，不把中止当安装成功。

新生命周期操作在写新计划前读取所有旧计划；未完成且无匹配原计划/原末条摘要的有效恢复记录时拒绝继续。恢复回执必须自洽、保留原账本，且目标恢复关联正确选择记录；原指针中止只允许精确原摘要，无指针中止只允许未提交安装。已妥善处置的历史操作不会因后续合法版本切换重新成为待处理；新操作仍须核验当前事实。
