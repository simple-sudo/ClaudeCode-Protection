# Protection 全机网络模式与受保护会话生命周期 V1

状态：**REQUIREMENT_ONLY / DESIGN（2026-11-12）**。这是正式目标和验收合同，不表示全机网络控制已实现、已安装或已实机验证。当前实施状态只见 [CURRENT-STATE](CURRENT-STATE.md)。

本版本取代 2026-11-04 的“仅临时全机 IPv6 出站门 + Claude 专属持久防直连”作为最终网络模式目标。原方案可作为历史设计理解，但不能继续限制当前正式需求。

## 1. 两个独立状态机

网络保护模式与 Claude 会话不是同一个生命周期。用户可以结束 Claude 会话而继续让整台电脑使用受保护的美国代理出口。

### 1.1 全机网络模式

| 状态 | 含义 | 必须行为 |
|---|---|---|
| INACTIVE | Protection 网络模式未启用 | 不改变用户现有网络行为，不保留本产品活动中的全机阻断策略 |
| PREPARING | 正在准备全机代理保护 | 先建立可验证的持久阻断，再核验代理和所有必要网络路径 |
| ACTIVE | 全机公网代理模式已建立 | 所有应用与系统服务的公网流量只允许通过指定 FlClash 代理路径 |
| DEGRADED | 代理、TUN、策略、监督或出口证据失效 | 阻断未授权公网出口，撤销 Claude 会话许可；不得回退直连 |
| EXIT_PENDING | 用户明确要求退出全机保护 | 核对会话和本产品资源归属；只有安全条件满足后才撤销本产品拥有的规则 |

### 1.2 Claude 会话

| 状态 | 含义 |
|---|---|
| NOT_RUNNING | 没有受保护 Claude 会话 |
| STARTING | 可信 Owner 正在创建并核验受限进程链 |
| RUNNING | Claude 及纳管工具处于实际受限身份、Job 和网络边界中 |
| STOPPING | 先撤销会话准入与转发，再精确停止并核验 Job/进程归属 |
| CLOSED | 进程归零、资源回收和闭合回执均得到证明 |

网络模式 ACTIVE 可以与 Claude 会话 NOT_RUNNING / CLOSED 同时存在。

## 2. 启用全机网络保护的顺序

1. 用户明确选择启用 Protection 全机网络模式。
2. 可信管理侧先安装并核验持久 WFP 出口屏障；屏障在代理检查失败、FlClash 退出或控制器崩溃时仍保持阻断。
3. 用户按正常方式启动并管理 FlClash，选择指定美国住宅代理、Global 模式和 TUN。Protection 不擅自更改节点或关闭代理。
4. 可信管理侧核验 FlClash Core 的真实映像身份、签名/哈希、进程创建身份、监听/连接归属、TUN 接口、代理端点集合和策略快照。
5. 核验代理出口属性及其有效期。国家/地区、ASN、住宅网络属性、中国关联网络风险和出口变化必须分别有证据；仅显示美国国家代码不够。
6. 核验 DNS、TCP、UDP、QUIC、IPv4、IPv6、回环代理入口、代理端点引导解析和物理网卡出口。任何未知、可达 DIRECT 或未授权端点均阻止进入 ACTIVE。
7. 只有全机网络门禁通过，网络模式才进入 ACTIVE。Claude 会话启动仍需单独完成 AppContainer/LPAC、Job、工具链、资源权限和 Owner 准入检查。

## 3. ACTIVE 状态的网络合同

- 全机所有应用和 Windows 服务的**公网/互联网出站流量**均须经过 FlClash TUN 与 Global 代理路径，不按进程名或 Claude 域名名单决定是否允许直连。
- 物理网络接口只允许 FlClash Core 向当前经核验的代理端点建立必要的外层传输连接。授权必须绑定真实进程身份、端点、协议、端口和有效期；节点切换必须先更新并重新核验授权。
- 所有其他应用、系统服务和未知进程的公网直连均拒绝。未知域名不是直连理由；代理不支持的协议也不得降级直连。
- IPv4 与 IPv6 均纳入。IPv6 公网流量若能经代理完整转发，可按同一标准放行；否则阻断。不能以当前没有 IPv6 连接或一次超时作为安全证据。
- DNS（UDP/TCP 53）、DoT（853）、DoH、QUIC/UDP 和其他替代协议必须逐项纳入。代理支持的流量经过代理；不支持或无法确认的流量阻断。
- ICMP/ICMPv6、ARP、DHCP、IPv6 ND/RA 等链路控制协议按必要性建立最小例外；不得将其例外扩大为任意公网或整个局域网直连。
- 回环只允许产品明确需要的本机端点，例如经身份核验的 FlClash 代理入口；不得因为目标是 127.0.0.1 就默认可信。
- 不允许对 UU 远程、浏览器、PowerShell、Python、MCP 或其他应用设置宽泛公网直连例外。

### 3.1 DNS 引导问题

FlClash 可能需要解析代理服务器域名才能建立外层连接，形成代理引导问题。该路径必须使用明确、受限、可审计的引导机制（例如固定/签名端点清单、可信解析器或经核验的缓存地址）。不得为了启动代理而开放系统默认 DNS 或运营商 DNS 的任意直连。

### 3.2 TUN 与 WFP 的分层要求

WFP 规则必须在正确的网络层区分“应用流量被 TUN 接管”与“FlClash Core 在物理接口建立代理外层连接”。不能在错误层级提前拦截合法 TUN 流量，也不能因为放行 FlClash 进程而赋予它任意公网访问权。需要通过实际网络层、接口、PID/映像身份和投递证据验证。

## 4. UU 远程与其他应用兼容性

用户报告：FlClash Global 美国代理开启时，UU 远程目前可以正常使用。这是**应用功能兼容性的初步用户观察**，不是全部 UU 网络流量均经代理的证明。

验收必须覆盖 UU 相关主进程、服务、子进程和后台组件，以及控制、画面、键鼠、文件传输、UDP/P2P、中继和重连路径：

- 若 UU 的所有公网通信能通过指定代理，且延迟与稳定性满足用户需求，可在不增加直连例外的前提下通过兼容性验收。
- 若某种 UDP/P2P 路径不能经代理，必须阻断该路径并观察 UU 是否能安全切换到代理可用的中继。
- 不得因“远程桌面必须可用”而允许 UU 连接中国关联公网端点或未经授权的物理出口。
- 同一局域网直连也不能自动豁免；只有必要、精确、用户批准且不会破坏网络隐私目标的本地路径才可单独评估。

其他日常应用采用相同原则：经指定代理正常使用；不能代理的公网协议阻断。用户表示全机美国代理不会影响日常使用，是产品兼容性目标，仍需实测验证。

## 5. 故障与安全关闭

以下任何情况都进入 DEGRADED：

- FlClash Core 退出、崩溃、映像身份变化或代理监听消失。
- 代理端点、节点、ASN/住宅属性或出口国家/地区超出已授权集合。
- TUN 接口丢失、路由漂移、出现 DIRECT/COMPATIBLE 直连回退。
- DNS、UDP、IPv6 或物理接口出现未授权旁路。
- WFP 策略、Broker、Owner、Watchdog 或持久状态不一致。
- 关键状态为 UNKNOWN、超时或无法读取。

进入 DEGRADED 后：

1. 持久 WFP 屏障继续阻断未授权公网直连。
2. 关闭全机代理转发许可，撤销 Claude 会话的网络租约。
3. 由原 Owner 先关闭 Claude 会话和纳管进程，再核验 Job 归零及资源回收。
4. 不自动关闭 FlClash，不自动恢复 IPv6，不自动开放物理网卡直连。
5. 记录最小化失败证据，等待用户处理并重新执行完整资格检查。

不能依赖 Watchdog 轮询在故障发生后补救；必须证明故障窗口内没有直连投递。

## 6. 退出与恢复

- 用户可以先停止 Claude 会话，同时保持全机网络模式 ACTIVE，继续让日常应用走美国代理。
- 只有用户明确选择“退出 Protection 全机网络模式”后，才进入 EXIT_PENDING。
- 退出前先确认 Claude 会话已闭合，所有本产品网络租约、进程和受控转发均已撤销。
- 精确移除本产品拥有的 WFP 规则和临时资源；不重置用户原有 FlClash 配置、节点、系统代理、网络接口或其他防火墙规则。
- 如果 FlClash 已提前关闭，持久屏障仍必须保持，直到用户明确确认退出保护模式。
- 恢复过程必须核验本产品规则确实移除、原有配置未被覆盖、未知规则未被删除。失败时保持明确状态，不做宽泛“清理”。

## 7. 独立本机信息隔离仍然必需

全机代理只证明网络路径，不证明 Claude 看不到本机真实信息。Claude 仍可能读取 SSID、网卡、路由、DNS、时区、设备 UUID、GPU 标识、UU/FlClash 配置，再通过允许的美国代理发送。

因此必须继续执行：

- Claude 及派生进程的实际文件、注册表、进程、服务、设备和管理接口权限隔离。
- 对 PowerShell、Python、Node.js、MCP、Hooks、后台 Supervisor 和独立辅助进程的身份与资源访问测试。
- 真实敏感内容的 L3 对抗实验、可信宿主原值对照和跨来源画像分析。
- 对受保护身份可见的外传数据、目标域名、DNS 和实际网络连接进行独立审计。

全机代理不替代 P0-HOST、P0-SELF 或 P0-ASSURANCE。

## 8. 验收门槛

| 验收域 | 必须证明 | 失败条件 |
|---|---|---|
| 全机 IPv4/IPv6 | 所有公网应用流量经代理，未授权物理直连零投递 | 任一直接公网投递或未知路径 |
| TCP/UDP/QUIC | 代理支持的经代理；不支持的明确阻断 | 协议降级直连 |
| DNS/DoH/DoT | 查询和引导解析均符合授权路径 | 运营商/系统 DNS 旁路 |
| FlClash 身份 | Core、端点、节点、出口及有效期绑定 | 仅凭进程名或端口放行 |
| 故障 Kill Switch | 崩溃、掉线、重启和漂移期间持续阻断 | 故障窗口直连 |
| UU 远程 | 功能可用且所有公网路径已核验 | 未知 P2P/中继直连 |
| 本机敏感信息 | Claude 及派生工具无法越权读取真实敏感内容 | 任一 P0 信息未经授权可见 |
| 生命周期 | 用户退出后精确恢复，未拥有资源不被改动 | 残留规则、误删或不明状态 |

每一项都必须记录工件 SHA、Windows 版本、身份、网络拓扑、代理端点证据、测试方法、实际投递/阻断证据、恢复结果和未覆盖范围。

## 9. 当前实现边界

现有 SessionProxy、固定 CONNECT/DoH 资格、FlClash 身份核验、WFP 持久规则和路由快照是有价值的局部基础，但不是本文件定义的全机公网出口产品实现。全机 TUN/WFP 分层、完整 DNS/UDP/IPv6、代理端点动态租约、UU 全流量兼容性和故障窗口证明均须单独实现与实机验收。
