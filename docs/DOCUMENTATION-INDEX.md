## 7. 历史文档和证据规则

- 日期文档中的“当前”只表示其记录日期，不代表当前安装、分支或授权。
- 不把历史失败改写成成功，也不把历史成功自动迁移到新工件。
- 不删除原始失败记录、哈希或边界说明来制造表面进度；纠错时新增带日期的更正并保留原记录。
- STATUS 是过程索引；PROJECT-ACCEPTANCE 是能力证据账本；CURRENT-STATE 保持精简。
- 文档冲突由 SECURITY-REQUIREMENTS 的现行目标裁决；机制细节由对应专题文档定义；状态只由 CURRENT-STATE 更新。

## 8. Public 仓库与真实证据

本仓库为 Public。设备所有者已明确接受将研发必要的真实主机信息、敏感字段和原始证据写入仓库。真实 IP/IPv6、MAC/BSSID、SSID、设备 UUID/序列号、私人路径、SID/ACL、进程/服务、代理/远控元数据、原始日志和失败回执，不得因公开属性而默认禁止或脱敏。按 [EVIDENCE-GOVERNANCE](EVIDENCE-GOVERNANCE.md) 保留真实值、来源、时间、执行身份和工件版本。

密码、有效 Token/Cookie、私钥、签名密钥和可重放代理认证凭据仍是独立认证秘密；真实读取路径必须测试，但有效凭据原值不作为普通证据意外提交。CI/Artifacts 不自动复制真实原始证据，正式 Claude 执行域不得继承研发证据访问权。
