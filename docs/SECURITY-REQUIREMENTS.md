## 证据与交付术语

这些标签是不同维度，不是自动升级的流水线：

| 标签 | 唯一含义 |
| --- | --- |
| REQUIREMENT_ONLY / DESIGN | 正式要求/设计；没有自动推导实现或实测 |
| SOURCE | 有源码/静态审查；静态或非生成检查不证明BUILD或运行 |
| BUILD | 确定输入与工具链的构建成功；不推导安装/行为正确 |
| INTEGRATED | 已接入指定源码调用链；是否实际执行另标VERIFIED |
| VERIFIED(scope) | 指定版本、身份、场景、时间的实测；必须写明范围及未覆盖项 |
| CAPABILITY_DELIVERED(scope) | 某个限定能力有可交付结果/使用路径与相应证据；不等于整机产品完成 |
| PRODUCT_DELIVERY_ACCEPTED | 完整产品全部必需项、运维与故障场景有验收依据，包括真实受保护Claude链 |
| FAIL / UNKNOWN / BLOCKED / NOT_RUN / DEFERRED_BY_USER | 分别保留失败、未知、阻塞、未执行和用户延期，不能相互替换或算PASS |

新记录不使用裸 `DELIVERABLE`。旧记录中的 `VERIFIED/DELIVERABLE` 按其明确切片解释为
`CAPABILITY_DELIVERED(scope)`；范围不明则记UNKNOWN，不追认完整产品交付。历史原文和哈希不改。
安装成功、GUI绿色、测试fixture、配置存在、进程消失或某个退出码均不能单独证明保护与恢复成功。

## 威胁模型与资源边界

目标对象是受保护的Claude官方主进程、派生工具及明确纳入的MCP/Hooks/后台组件。
不得依靠命令名、提示词、自报身份或初始进程树推导边界；实际身份、资源访问、句柄/IPC与网络
必须由Windows执行约束。独立后台组件和共享浏览器分别说明支持范围，不能粗暴限制整个浏览器。
可信用户保留维护权；不承诺对抗宿主最高权限/内核攻击者、完全隐身或消除全部侧信道。

授权工作区/工具/GPU只授予明确所需能力，不等于整个用户账户、磁盘、宿主进程或管理员权限。
数据导入由普通侧显式选择，不能由Broker按不可信路径读取宿主文件；数据授权不等于代码执行授权。
保护系统自身源码和管理资源默认排除于日常Claude工作区。可信维护者的明确维护授权另行审核，
不能由Claude自报“维护”或选择一个父目录扩大权限。本轮可信开发工作不自动授权将本仓库暴露给受保护Claude。
GitHub/依赖访问权限也不应继承宿主维护者的凭据、仓库管理权或本保护项目访问权；
远端源码与备份的访问控制需要独立设计，不能仅凭本地源码已分离就声称远端不可获取。

## P0：不可互相替代的安全主线

P0-HOST、P0-NET、P0-SELF同属必需安全目标；新增自我保护不降低既有网络或宿主隐私优先级。

| ID | 正式要求 | 后续验收依据（本轮不执行） |
| --- | --- | --- |
| P0-HOST | 隔离未授权文件、注册表、凭据、代理/远程软件配置、敏感进程、管理接口和辅助服务；保护真实位置、网络/设备标识及秘密 | 授权工作可用与同身份越权拒绝成对验证；多工具/替代API覆盖；不存在/超时/缺身份不算拒绝通过 |
| P0-NET | 强制授权通道，未授权TCP/UDP/DNS/IPv6及代理绕回宿主/私网管理资源均不得成为旁路；故障不回退直连 | 同一会话身份、真实可达对照和投递/阻断证据；规则及最终目的地核验，代理/控制器故障与漂移验证 |
| P0-SELF-READ | Claude及派生进程未经授权不得读取本机保护源码、凭据、内部配置、敏感日志/状态、管理通信内容或控制接口 | 在真实受保护身份下对明确对象/权限做最小非秘密探测，并保留可信维护正控制；不得先读取真实秘密再声称测试安全 |
| P0-SELF-CONTROL | 不得未经授权篡改、停止、卸载、覆盖、注入、借句柄/接口或绕过运行中的保护系统 | 权限/IPC鉴权、安装与更新完整性及跨工具越权矩阵；不能只验证文件不可写或按EXE名过滤 |
| P0-SELF-CHILD | PowerShell、Python、Git、Node.js、MCP、编译器等派生路径保持相同限制；独立组件不得逃逸身份范围 | 同创建链/Job/实际token与最小资源授权验证，必要工作仍可用；没有高权限shell或通用Broker执行器 |
| P0-SELF-FAILURE | 保护组件异常退出不得使Claude取得额外资源/网络；先保持或恢复拒绝边界，再精确停止/恢复 | 具体异常、控制器退出、崩溃/重启的拒绝边界、归属/闭合回执及恢复证据；组件消失不算清理成功 |
| P0-SELF-MAINTAIN | 可信用户可正常诊断、升级、恢复、回滚和卸载；维护不能被锁死，也不能成为Claude可借用的旁路 | 固定操作、最小权限、身份/版本绑定、审计与可恢复性；仅处置本安装可证明拥有的资源，保留原配置及失败材料 |

安装文件DACL、一次LPAC拒绝或原始屏障是部分机制证据，不能直接覆盖整个P0自我保护目标。
不要把“未公开用途”当作管理接口鉴权。程序异常时仍需独立有效的拒绝边界，而非只依赖轮询发现后补救。

## P1：真实有效信息最小暴露

最小暴露是主线，辅助混淆是次要增强。Claude没有默认获知保护用途及内部设计的权限。
在保持可信维护与可诊断性的前提下，减少无必要的程序/服务名与描述、安装路径/版本元数据、
命令参数、内部通信及管理接口细节、策略、日志、状态、运行架构和本地开发资料暴露。
宿主环境画像、持久软件标识和非必要遥测延续既有最小化要求；敏感真实标识仍按P0-HOST保护。

开发项目仍叫ClaudeCode-Protection。正式运行组件可以采用中性名称，但须先形成一致的
命名/发布身份方案：覆盖进程、服务、目录、版本资源、IPC、日志和诊断映射，并评估升级、
包签名/哈希、对象所有权、恢复与卸载兼容性。没有选定或实施新名称；不能只改EXE名。
中性名称不是伪造发布者/签名，也不得用于躲避卡巴斯基等安全软件。真实权限拒绝必须在用途已被识别时仍成立。

后续应记录“暴露哪些字段、用途、谁能读、是否必要、如何最小化、可信侧如何诊断”，
以新增信息价值和兼容性作为评估依据，不以“无法从进程列表猜出用途”为安全验收。

## P2：有限、可维护的辅助混淆

只研究低成本、低暴露并可撤销的增强；不作为P0完成的前置替代或核心边界。
不得制造大量无意义后台进程、冒充微软/第三方真实签名或发布者、引入Rootkit/危险内核Hook，
或破坏Windows安全机制。不得损害性能、可靠性、诊断和可信维护。
若采用诱饵，必须无敏感数据、无额外特权、无新的控制入口，并先比较实际信息收益与运行/维护成本。
即使Claude识别保护用途，仍应无法越权干涉；不承诺永不被发现。本轮没有采用诱饵或混淆实现。

## 完整产品必须保留的能力

- Windows原生产品主链复用原安装→Broker→ProtectedSession→身份/Job/WFP→工作区/工具→监督/恢复。
  无默认完整VM、CPU-only替代、不受限沙箱回退或平行通用执行器。
- 十四项可信准入：代理内核、TUN适用性、出口IP、IP一致性、时区、Locale、IPv6、DNS、WebRTC、
  Watchdog、路由、客户端语言、ASN、Claude生态可达性，沿用[原逐项定义](PRODUCT-DIRECTION-20261027.md#十四项环境体检及强制准入)。
  由可信所有者结合独立系统安全条件、实时安装/token/Job/WFP及工作区/工具/设备授权执行；
  GUI报告、旧PASS和合成资格入口不能签发正式会话许可。严格策略的FAIL/UNKNOWN/过期不得放行；
  不适用必须有明确场景依据，不能用来抹掉未知或跳过必需安全项。
- 授权开发/编译/测试、依赖下载、必要本地MCP/服务与NVIDIA计算应在同一边界内可用。
  宿主GPU发现或未隔离计算不替代选定隔离身份内的代表性CUDA/PyTorch及结果验证。
- IPv4强制通道为主；IPv6转发/线路优化不是当前功能要求，但IPv6阻断与必要负向验收不可删。
  日常FlClash/UU及宿主网络保持；全机变更只能作为必要、明确选择、影响已审查且可恢复的独立能力。
- 普通GUI/维护、可信安装/更新、长时稳定、异常退出/重启、恢复/卸载和真实受保护Claude执行链
  均属整机验收；真实Claude仍延期且未测试时，不得标PRODUCT_DELIVERY_ACCEPTED。

## 长期源码分离与部署

未来本机只保留已验证的正式运行组件，完整开发源码与日常Claude运行环境分离。
项目完成后可将完整源码迁至离线加密U盘，并保留独立加密备份。迁移前需具体清单、
加密/密钥可用性、完整性核验、恢复演练和交付验收，保留Git历史和恢复能力。
**完成安全迁移与交付验收之前不得删除本机项目或现有GitHub仓库。**迁移、加密、删除、
中性命名部署均是未来设计，本轮未执行；这不是现在的迁移/删除授权，也不是远端访问权限保证。
