# 现行安全需求与交付语义

生效：2026-11-02；2026-11-03及2026-11-04按用户最新安全理念、手动代理/IPv6 生命周期及真实数据对抗实验授权更新。整合既有宿主隔离、强制网络、开发工具/GPU、
可信准入、生命周期、自我保护和信息最小暴露，并明确硬件个体身份及跨来源关联保护。本页是现行需求入口；
实现/安装/授权情况只见[当前状态](CURRENT-STATE.md)。**需求成立不等于机制已实现或获准运行。**

## 根本目标与共同交付条件

让Claude Code及其派生进程在真实Windows电脑上正常开发、使用授权网络与GPU，同时不能越权
识别宿主物理个体、读取真实敏感网络环境和远程控制端信息，或从多个未经授权的数据源拼接用户画像。
功能可用性、宿主信息保密、跨来源关联保护必须同时纳入设计和验收，不能以其中一个替代另两个。
目标不要求制造虚假的美国电脑、隐藏所有硬件型号，或随机化全部普通硬件属性。

最终判断：同一受控环境中的Claude能完成授权开发，不能通过可用系统接口越权获得真实宿主身份、
网络关联及敏感资源，且故障时保护边界仍成立。正常美国代理出口、CUDA计算成功与隐私隔离分别验收。
2026-11-04新增手动 FlClash、GUI 启停及临时全机 IPv6 门，但当前仅 REQUIREMENT_ONLY / DESIGN；
本次不开发、不改变系统或实际启动 Claude，不解除现有运行资格及具体授权边界。

## 证据与交付术语

这些标签是不同维度，不是自动升级的流水线：

| 标签 | 唯一含义 |
| --- | --- |
| REQUIREMENT_ONLY / DESIGN | 正式要求/设计；没有自动推导实现或实测 |
| SOURCE | 有源码/静态审查；静态或非生成检查不证明BUILD或运行 |
| BUILD | 确定输入与工具链的构建成功；不推导安装/行为正确 |
| INTEGRATED | 已接入指定源码调用链；是否实际执行另标VERIFIED |
| VERIFIED(scope) | 指定版本、身份、场景、时间的实测；必须写明范围及未覆盖项 |
| CAPABILITY_DELIVERED(scope) | 某个限定能力有可交付结果/使用路径与相应证据；不等于整机产品完成 |
| PRODUCT_DELIVERY_ACCEPTED | 完整产品全部必需项、运维与故障场景有验收依据，包括真实受保护Claude链 |
| FAIL / UNKNOWN / BLOCKED / NOT_RUN / DEFERRED_BY_USER | 分别保留失败、未知、阻塞、未执行和用户延期，不能相互替换或算PASS |

新记录不使用裸 `DELIVERABLE`。旧记录中的 `VERIFIED/DELIVERABLE` 按其明确切片解释为
`CAPABILITY_DELIVERED(scope)`；范围不明则记UNKNOWN，不追认完整产品交付。历史原文和哈希不改。
安装成功、GUI绿色、测试fixture、配置存在、进程消失或某个退出码均不能单独证明保护与恢复成功。

## 威胁模型与资源边界

目标对象是受保护的Claude官方主进程、派生工具及明确纳入的MCP/Hooks/后台组件。
不得依靠命令名、提示词、自报身份或初始进程树推导边界；实际身份、资源访问、句柄/IPC与网络
必须由Windows执行约束。独立后台组件和共享浏览器分别说明支持范围，不能粗暴限制整个浏览器。
可信用户保留维护权；不承诺对抗宿主最高权限/内核攻击者、完全隐身或消除全部侧信道。

授权工作区/工具/GPU只授予明确所需能力，不等于整个用户账户、磁盘、宿主进程或管理员权限。
数据导入由普通侧显式选择，不能由Broker按不可信路径读取宿主文件；数据授权不等于代码执行授权。
保护系统自身源码和管理资源默认排除于日常Claude工作区。可信维护者的明确维护授权另行审核，
不能由Claude自报“维护”或选择一个父目录扩大权限。本轮可信开发工作不自动授权将本仓库暴露给受保护Claude。
GitHub/依赖访问权限也不应继承宿主维护者的凭据、仓库管理权或本保护项目访问权；
远端源码与备份的访问控制需要独立设计，不能仅凭本地源码已分离就声称远端不可获取。

## 2026-11-04 新增 P0：仅对 Claude 限制的敏感信息与真实内容强制实验

**正式最高优先级研发原则，完整合同见[真实敏感数据强制对抗实验规范](REAL-DATA-ADVERSARIAL-ASSURANCE.md)。**

**定义范围**：本项目所列宿主 IP/IPv6、Wi-Fi、运营商/ASN、中国关联连接、FlClash/UU、
设备唯一 ID、地理位置、系统指纹与跨源画像等“敏感信息”，是**对于 Claude Code、
Claude 官方服务及其相关进程**必须阻断的读取/外传目标；不是对 Codex、ChatGPT、
授权开发人员和其他软件的全局保密/禁读定义。

**研发所有者授权**：设备所有者明确允许 Codex、ChatGPT 与可信项目研发组件，
为本人控制的 Windows 主机与网络环境，**充分真实读取、获取、检查、分析和关联上述实际信息**；
即使研发工具使用云端模型，也不得据此默认跳过或限制必要实验。用户许可覆盖相应真实内容
研究，不以“少接触/尽可能绕开”作为开发原则，也不因字段名带“敏感”逐项反复申请许可。
**本授权不传递给正式 Claude/其工具链或其他未经授权方**；不扩张到攻击第三方系统、
无关账户、认证秘密的非研发使用或任意高权限系统操作。

**强制最高等级实验**：不得只用合成样本、固定拒绝码、单一文件 DACL、命令黑名单、
静态检查或脱敏摘要宣称安全。应主动覆盖每类关键信息的真实可能路径（文件、注册表、
COM/CIM/WMI、网络/设备/驱动 API、进程、服务、日志、子工具与管理端点），
从可信宿主侧核验真实参考值，再以与 Claude 相同的**实际受限身份**尝试读取真实内容；
若读取成功，可信研发侧必须审查具体原值、溯源并进行跨来源画像推断/风险整改，
而不是只登记布尔可读。按 L1=合成、L2=真实权限/对象、**L3=真实内容尝试与核验及画像分析**
分级；重要 P0 信息目标的 L3 为正式验收必要证据，不能少、不能省、不能故意回避。
访问拒绝、目标缺失、超时、受限身份不明、未覆盖路径不能夸大成完整安全证明。

**强制区分信息流**：可信研发者可在受控证据环境审阅真实原值并按用户授权与 Codex/ChatGPT
进行分析；普通产品 GUI/公开报告/源码仓库不默认承载原始证据，**正式 Claude 及 Anthropic
官方通道不得因测试而获得原始宿主数据**。产品自动自评/画像引擎仍采用可信本地确定性逻辑、
不以 LLM 自动决策；**这不禁止研发阶段的 Codex/ChatGPT 模型分析**。真实认证令牌/私钥的
测试读取仍要覆盖，原值使用和传播则按独立认证秘密边界处理，不得成为省略其他真实测试的理由。

**授权与高影响边界独立**：普通必要真实信息只读/分析具有设备所有者现行研发许可；
安装、UAC、ACL/WFP/IPv6 修改、FlClash 开关、真实 Claude 启动、系统故障注入仍需当前
具体操作门禁和必要人类决定。历史文档“不能读真实秘密/只做无秘密最小探测”仅解释旧实验的
当时范围，不能推翻当前真实内容强制实验原则；**P1 对生产 Claude 的最小暴露不等于
对开发者最小实验数据接触**。

## 2026-11-04 新增 P0：手动代理、受保护启动与 IPv6 恢复

详见[受保护启动与安全退出生命周期 V1](PROTECTED-STARTUP-SHUTDOWN-LIFECYCLE-V1.md)。正式启动顺序：
**先打开 ClaudeCode-Protection 点击「准备启动」→可信 owner 确认全机原生 IPv6 出站阻断且 Claude 永久防直连有效→用户手动开启 FlClash Global + TUN 和美国住宅节点→返回「开始检查」→原十四项与 P0 安全准入通过→由 GUI「启动 Claude Code」**。
不能先在普通终端运行 Claude 再补加限制，也不能由保护程序自动改变 FlClash 节点、模式、开关。

关闭顺序：**GUI「一键关闭所有 Claude 进程」→owner 先撤销转发/准入并维持隔离，再验证实际 Job/子进程/连接全部安全退出→GUI 提示可手动关闭 FlClash→用户自己退出 FlClash→回 GUI 明确点击「恢复 IPv6」**。若用户继续使用代理可不恢复 IPv6。恢复只撤销本安装拥有的**全机临时**原生 IPv6 外联规则，**始终保留 Claude 独立的持久 IPv4/IPv6 防直连规则**。原生 IPv6 阻断不是卸载/全局禁用协议栈，必要链路和合法代理底层连接另行明确审查。

代理/TUN/节点/规则/owner 故障**不是**用户主动关闭：预先有效的 WFP 应阻断直连；立即撤销会话许可、关闭既有转发并尽快终止受控进程，保持全机 IPv6 阻断且**绝不自动恢复**。仅有 Watchdog 轮询不能保证没有故障窗口；旧连接、脱离 Job 的相关进程、外部自行启动路径及重启恢复必须验收。Global + TUN 和单次出口显示美国不能单独证明全机应代理互联网流量均经住宅出口，基础物理连接、DNS、UDP、IPv6 与必要例外均需具体证据。

全机 IPv6 门是用户明确新增的**有限范围系统控制**，不是要求 ClaudeCode-Protection 接管 FlClash 或取代全机网络引擎。所有系统更改另需固定影响、权限、回滚和具体人类决定；不可为兼容而放开 Claude 对 FlClash/UU、运营商、位置、机器唯一标识、管理接口或画像关联信息的访问。

## P0：不可互相替代的安全主线

P0-HOST、P0-NET、P0-SELF同属必需安全目标；新增自我保护不降低既有网络或宿主隐私优先级。

| ID | 正式要求 | 后续验收依据（本轮不执行） |
| --- | --- | --- |
| P0-HOST | 隔离未授权文件、注册表、凭据、代理/远程软件配置、敏感进程、管理接口和辅助服务；保护真实位置、稳定硬件个体标识、真实网络/远控关联及秘密，限制未经授权来源的画像拼接 | 授权工作可用与同身份越权拒绝成对验证；多工具/替代API及跨来源覆盖；不存在/超时/缺身份不算拒绝通过 |
| P0-NET | Claude 与相关进程永久仅用授权代理；禁止未经授权的 IPv4/IPv6/TCP/UDP/DNS/管理接口直连；新增用户主动的全机原生 IPv6 临时出站阻断/恢复；代理故障不退回直连、不自动恢复 IPv6 | 实际会话身份/全部工具链、已建连接、规则持久性与网络投递证据；主动关代理、故障、控制器退出、重启和 IPv6 恢复独立验收 |
| P0-SELF-READ | Claude及派生进程未经授权不得读取本机保护源码、凭据、内部配置、敏感日志/状态、管理通信内容或控制接口 | 在真实受保护身份下对明确对象/权限做最小非秘密探测，并保留可信维护正控制；不得先读取真实秘密再声称测试安全 |
| P0-SELF-CONTROL | 不得未经授权篡改、停止、卸载、覆盖、注入、借句柄/接口或绕过运行中的保护系统 | 权限/IPC鉴权、安装与更新完整性及跨工具越权矩阵；不能只验证文件不可写或按EXE名过滤 |
| P0-SELF-CHILD | PowerShell、Python、Git、Node.js、MCP、编译器等派生路径保持相同限制；独立组件不得逃逸身份范围 | 同创建链/Job/实际token与最小资源授权验证，必要工作仍可用；没有高权限shell或通用Broker执行器 |
| P0-SELF-FAILURE | 保护组件异常退出不得使Claude取得额外资源/网络；先保持或恢复拒绝边界，再精确停止/恢复 | 具体异常、控制器退出、崩溃/重启的拒绝边界、归属/闭合回执及恢复证据；组件消失不算清理成功 |
| P0-SELF-MAINTAIN | 可信用户可正常诊断、升级、恢复、回滚和卸载；维护不能被锁死，也不能成为Claude可借用的旁路 | 固定操作、最小权限、身份/版本绑定、审计与可恢复性；仅处置本安装可证明拥有的资源，保留原配置及失败材料 |
| P0-ASSURANCE-SELF | 可信侧对实际 Claude/完整工具链进行自我安全评估，强制主动真实内容获取尝试、多路径覆盖与合法开发正控制；评估器不可自授运行许可 | 原 owner 绑定真实 token/Job/版本/范围；可信宿主真实原值正控制、同身份真实读取/拒绝、合法功能正控制；L3 证据、暴露/拒绝/UNKNOWN/未测分级及防报告伪造 |
| P0-ASSURANCE-PROFILE | 可信本地确定性引擎以受限身份实际可见的真实字段和内容进行网络/位置/设备画像关联，单点 P0 泄露一票阻断；允许授权 Codex/ChatGPT 开发分析 | 真实内容来源图、直接事实/推断/UNKNOWN、同源去重、跨来源候选与残余风险；合成规则测试不代替 L3 真实内容和 LPAC/工具链实测 |

安装文件DACL、一次LPAC拒绝或原始屏障是部分机制证据，不能直接覆盖整个P0自我保护目标。

## P0-ASSURANCE：可信自评与指纹画像重建

两系统是 P0-HOST / P0-NET / P0-SELF 的**验证和关联风险判断能力**，不替代 Windows 强制边界、
可信 owner 运行准入或完整开发功能。自评必须对真实受保护身份实施充分多路径真实内容获取尝试、可信宿主真实参考值对照
和授权开发正控制；画像只将该受限身份实际可见、有来源及有效期的内容判作 Claude 泄露，不得把管理员环境中可见的
宿主秘密视为 Claude 可见事实。各个结论必须标明 CONFIRMED_DIRECT、INFERRED_WITH_BASIS 或 UNKNOWN，
并留存独立来源、竞争解释及未覆盖路径。禁止用泄露数量/“画像百分比”抵消单项关键隐私泄露。

**中国关联网络端点（包括第三方 UU 中继）**、真实物理网络、设备唯一身份、FlClash/UU 敏感控制数据
一旦被证明未经授权可见，按 P0 发布阻断；证据不足不是已证实泄露，但必需门禁未知时仍不得放行。
正常美国代理出口属于授权观察，不证明使用者处于美国，也不授权本地网络管理数据可读。

**产品内自动自评与画像运行判定器**不得使用本地/云端 AI 或自动向外部上传原始证据；
**但用户授权的 Codex/ChatGPT 研发及真实数据分析不受这一引擎限制**，可审查必要真实原值。
两系统必须在可信域内运行并受到保护；Claude/派生工具不能访问其源码、规则、评估基准、管理通信、原始证据和
报告，不能通过伪造自评结果签发权限。可信策略可据风险要求原有 owner 保持隔离、阻断准入或
实施经授权的有界修复；不会自动获取管理员权限、改动 FlClash/UU 或重试有风险的系统操作。
运行时评估是对强制隔离的补充，不是轮询式事后拦截的替代品。

具体模块职责、证据合同、确定性推理、开发次序与验收矩阵见
[可信自评与画像评估专题](ASSURANCE-AND-EXPOSURE-PROFILING.md)。

## 信息目标与多路径隐私验收

  真实原值在可信证据区保留必要的研发审阅能力，并可按所有者授权供 Codex/ChatGPT 分析；Git/CI、公开报告和正式 Claude 工具结果不默认存放这些原始材料。

### 真实网络身份与远控关联

授权美国住宅代理只授权使用该出口；以下未经授权的宿主信息源及其关联线索属于P0-HOST：

- 中国电信、中国联通、中国移动及其他真实运营商关联线索；即使只是第三方服务器的运营商归属，
  也不能因它不是家庭公网IP或用户实际运营商而降为允许暴露。
- 物理网络连接、网卡、路由、DNS、网络接口和TCP/UDP连接状态。
- UU远程服务节点、会话元数据、控制端关联、日志、配置和设备信息；FlClash真实节点、网络路径、
  管理接口和内部连接数据；其他可还原远控端身份或位置的未经授权信息。
- 通过COM/CIM/WMI、Windows网络API、事件、注册表、文件、进程及其他路径间接还原上述事实的来源。

本次用户报告现场Windows中GameViewerServer.exe存在与中国电信相关地址的TCP连接；
这里只记录风险线索，不记录地址，不重新审计。远端地址不能直接证明家庭宽带公网IP、手机/平板运营商，
但可能揭示宿主与中国网络基础设施的关联。管理员PowerShell已观察到数据，与实际LPAC受保护进程
能否读取，是两类证据；本轮未获得后者结果，不能据前者判定保护缺口已实测成立或已阻断。
美国代理正常工作不等于宿主网络身份安全；P0-NET通信强制不能替代P0-HOST信息读取隔离。

### 应用持久标识、会话状态与关联边界

分别研究四类风险：物理设备确定性身份、Claude Code/工具链/配置自行生成的持久设备标识、
不同授权会话间非必要本地状态共享，以及普通硬件能力和项目内容形成的概率性关联。
优先处理真实硬件唯一标识和非必要本地长期共享状态；必要项目连续性与工具功能须保留并明确授权。
应用标识不因并非硬件生成就自动安全，也不能仅凭状态重置声称不再关联。

跨账号隔离不能保证服务端无法关联账号；平台认证、安全机制及已有服务端记录不由本机资源隔离消除。
不得篡改第三方认证或安全机制来宣称不可关联，也不要求随机化所有普通能力或损害正常开发。

### 按信息目标选择保护措施

1. 不必要的信息优先由操作系统实际拒绝访问。
2. 必要真实能力保留功能，限制附带的不必要身份数据。
3. 必须使用但无需暴露后台细节的资源，由原可信Broker、受控网关或有限接口提供能力。
4. 确实需要稳定非敏感标识的功能，研究独立于真实硬件的替代标识及其授权作用域和生命周期。
5. 只需部分信息的功能，在可验证前提下减少精度和可见范围。

借鉴iOS隐私机制、虚拟数据或虚拟环境均不是预设答案。仅当替代数据比直接拒绝更有用、更安全、
更可维护时才考虑；必须与整体暴露面自洽、实际可用、来源受控、生命周期清晰且内部一致，
其他路径不能读回真实信息。无法自洽可能增加画像线索或副作用，须记录并重新选择措施。
简单API Hook、PowerShell输出替换、字符串过滤和伪造网络连接表不能充当真实宿主安全边界。

### 每类风险的验收记录

沿原所有者记录以下内容，不能只登记某命令/文件/API被拒绝：

| 必填项 | 记录要求 |

## P1：真实有效信息最小暴露

最小暴露是主线，辅助混淆是次要增强。Claude没有默认获知保护用途及内部设计的权限。
在保持可信维护与可诊断性的前提下，减少无必要的程序/服务名与描述、安装路径/版本元数据、
命令参数、内部通信及管理接口细节、策略、日志、状态、运行架构和本地开发资料暴露。
宿主环境画像、持久软件标识和非必要遥测延续既有最小化要求；敏感真实标识仍按P0-HOST保护。
必要受控环境视图、非必要标识最小化及信息一致性纳入P1；不能据此把P0敏感个体身份或网络关联降级。

开发项目仍叫ClaudeCode-Protection。正式运行组件可以采用中性名称，但须先形成一致的
命名/发布身份方案：覆盖进程、服务、目录、版本资源、IPC、日志和诊断映射，并评估升级、
包签名/哈希、对象所有权、恢复与卸载兼容性。没有选定或实施新名称；不能只改EXE名。
中性名称不是伪造发布者/签名，也不得用于躲避卡巴斯基等安全软件。真实权限拒绝必须在用途已被识别时仍成立。

后续应记录“暴露哪些字段、用途、谁能读、是否必要、如何最小化、可信侧如何诊断”，
以新增信息价值和兼容性作为评估依据，不以“无法从进程列表猜出用途”为安全验收。

## P2：有限、可维护的辅助混淆

只研究低成本、低暴露并可撤销的增强；不作为P0完成的前置替代或核心边界。
不得制造大量无意义后台进程、冒充微软/第三方真实签名或发布者、引入Rootkit/危险内核Hook，
或破坏Windows安全机制。不得损害性能、可靠性、诊断和可信维护。
若采用诱饵，必须无敏感数据、无额外特权、无新的控制入口，并先比较实际信息收益与运行/维护成本。
即使Claude识别保护用途，仍应无法越权干涉；不承诺永不被发现。本轮没有采用诱饵或混淆实现。

## 完整产品必须保留的能力

- Windows原生产品主链复用原安装与核验→可信Broker→ProtectedSession→LPAC/Job/WFP→授权工作区/工具→网络网关→监督/停止/恢复。
  无默认完整VM、CPU-only替代、不受限沙箱回退或平行通用执行器。
- 十四项可信准入：代理内核、TUN适用性、出口IP、IP一致性、时区、Locale、IPv6、DNS、WebRTC、
  Watchdog、路由、客户端语言、ASN、Claude生态可达性，沿用[原逐项定义](PRODUCT-DIRECTION-20261027.md#十四项环境体检及强制准入)。
  由可信所有者结合独立系统安全条件、实时安装/token/Job/WFP及工作区/工具/设备授权执行；
  GUI报告、旧PASS和合成资格入口不能签发正式会话许可。严格策略的FAIL/UNKNOWN/过期不得放行；
  不适用必须有明确场景依据，不能用来抹掉未知或跳过必需安全项。
- 授权开发/编译/测试、依赖下载、必要本地MCP/服务与NVIDIA计算应在同一边界内可用。
  宿主GPU发现或未隔离计算不替代选定隔离身份内的代表性CUDA/PyTorch及结果验证。
- IPv4 强制代理为主，不开发 IPv6 代理转发/线路优化；Claude 独立 IPv4/IPv6 持久防直连与用户主动的全机原生 IPv6 临时外联门是不同规则。
  仅安全退出、用户手动关闭 FlClash 和 owner 再次核验后恢复普通 IPv6，绝不撤销 Claude 屏障；FlClash/UU 日常使用保持，必要全机变更须具体审查并可恢复。
- 普通GUI/维护、可信安装/更新、长时稳定、异常退出/重启、恢复/卸载和真实受保护Claude执行链
  均属整机验收；真实Claude仍延期且未测试时，不得标PRODUCT_DELIVERY_ACCEPTED。
