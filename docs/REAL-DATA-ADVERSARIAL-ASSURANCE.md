> 本文是持续研发授权语义和测试目标，不表示新工具、系统变更、实际敏感读取或正式 Claude 验收已经完成。

## 1. 必须先说清楚的定义和授权

**本项目所称“敏感网络/设备/位置/指纹/画像信息”，是一组相对于 Claude Code、Claude 官方服务、
相关进程及其未经授权的数据通道的保护目标（简称“Claude 受限信息”），不是对所有软件、
所有开发者、Codex、ChatGPT 或所有 AI 的全局读取禁令。**

设备/本机网络环境所有者明确授权可信项目开发者使用 Codex、ChatGPT 和必要研发工具，
为**本人控制的 Windows 主机及其本地环境**进行真实敏感数据读取、检查、保存必要实验原始证据、
交叉分析和漏洞修复；**即使 Codex/ChatGPT 为云端模型，也不得因此把已授权研发变成只能使用模拟数据**。
该授权覆盖本项目所定义的信息目标和必要的真实读取实验，不需要因为字段属于这一定义就每次重新申请许可。
不把对正式 Claude 的读取禁令错误套用到授权研发工具；也不让正式 Claude 继承任何研发权限。

用户指定的受保护对象包括：宿主物理 IP/IPv6、Wi-Fi SSID/BSSID/MAC、网络接口/路由/DNS/
TCP/UDP 连接、运营商与中国关联端点（包括第三方 UU 中继）、FlClash 配置/节点/管理与路径、
UU/MuMu 远控配置/会话/网络/日志、系统位置与区域/时区/语言/字体等线索、
GPU UUID 和主板/BIOS/硬盘/设备稳定 ID、应用持久标识、保护系统资源与跨来源画像关联。
这些信息可能通常对其他 Windows 软件可读；**本项目仍要求 Claude 不可越权读取**。

此授权不把第三方设备、远端服务或他人账户变成测试靶标；对本机现有连接/第三方中继的**本机可见元数据**
可按授权测试，不等于对外部第三方服务器进行攻击。账号密码、私钥、认证令牌等具备实际认证能力的秘密
仍应区分于普通宿主指纹字段：不能因此取消真实越权测试，原始秘密的进一步复制/使用和高风险动作
按具体目的、安全边界与操作许可控制，不能将真实凭据直接用于未授权联网或提交。

## 2. 角色边界：研发读取与 Claude 泄露是相反的职责

| 角色 | 真实敏感内容权限与职责 |
| --- | --- |
| 设备所有者 | 决定个人设备/网络研发范围，授权查看实际原值、来源、结果与画像；高影响系统操作继续按现行程序决定。 |
| Codex / ChatGPT / 授权开发者 | **积极读取、分析所需真实本机内容并构建测试**；可为必要研发处理这些数据，包括经用户允许的云端分析。不得以“Claude 敏感/云端模型”为由自动回避。 |
| 可信宿主基准/测试 owner | 采集真实参考值、证明来源和对象身份，封存实际读取结果，并向授权研发者提供原始内容审查通道；严格区分宿主可读与 Claude 可读。 |
| 与 Claude **同等受限身份**的本地对抗探针 | 主动使用真实 API/工具尝试**获取真实内容**；读取成功是安全发现而不是授权行为。探针必须受原 OS/Job/WFP/管理者边界控制，不能因测试需要扩权。 |
| 正式 Claude Code/官方服务/相关进程 | 在日常运行和正式验收中**不获得未经授权的宿主信息**；测试权限、研发基准和原始报告不得进入它的可读工作区、工具输出或官方服务通信。 |

“真实 Claude 等价”不是由程序名或自报身份认定，而是需有可信 owner 的实际 token/LPAC/Job/
WFP/创建链/权限/有效版本证据。真实探针不等于真实官方 Claude 完整验收。

## 3. 真实数据测试是强制主线，不得人为减少、简化或规避

1. **必须测试实际内容**：先由授权可信宿主侧取得必要的真实基准，再由同等受限身份通过多条
   候选路径实际尝试读取；若成功，可信隔离侧检查获得的**具体原值**（包括与参考的差异、派生字段、
   真实网络/身份含义），而不只记录布尔“可读”、退出码或 Access Denied。受保护侧应被拒绝时
   就以拒绝和宿主真实基准形成正反对照，**不能为凑齐成功读取而给受限进程加权限**。
2. **不能少、不能省、不能绕**：按信息目标建立覆盖文件、注册表、WMI/CIM/COM、Windows API、
   网络连接、驱动/PnP/NVML、服务/管理端点、日志、进程/句柄、语言/时区与不同工具/子进程的
   攻击面矩阵；对已知、合理怀疑、跨源替代的实际路径开展足够实验。不可用固定十四角色、一个
   AccessDenied、合成对象或少量探针代替广泛真实调查。某路径不可行/不可测要说明，不能隐去。
3. **强制 L3 证据优先**：L1=模拟和规则逻辑，L2=真实对象/受限身份/权限结果，
   **L3=真实受限身份实际尝试获取真实内容 + 可信 owner 核验实际原值与来源 +
   有依据的跨来源画像分析**。对重要信息目标，L3 属正式隐私验收必要证据；
   不能用 L1/L2 替代，也不能为了减少真实数据接触而降低等级。L3 未完成标 NOT_RUN/UNKNOWN，
   属必要准入门时保持未验收。
4. **见到泄露就分析并修复**：若同身份受限执行域实际获得禁止字段，记录
   CONFIRMED_EXPOSURE（含真实字段/来源/权限/版本/时间/工具路径），评估直接事实、竞争解释、
   ASN/运营商/远控/位置/设备稳定标识及跨源可关联画像；明确修复权限/API/网关或替代来源，
   修复后同路径及替代路径复验。单个关键 P0 实际泄露不能被大量拒绝结果抵消。
5. **不伪造不夸大**：可信管理员直接读得到 ≠ Claude 读得到；接口返回成功但无有效内容、
   目标不存在、超时、未执行或只读到代理公开出口 ≠ 已完成 L3。未覆盖面列成 UNKNOWN；
   真实已获原值与基于它的推断分别记录，不能据美国住宅出口确认真实所在地。
6. **合法能力一起验证**：在不牺牲上述覆盖度的前提下，同身份确认正常项目/Git/网络/依赖/GPU
   可用；测试范围由真实风险与可复现路径决定，不以“越少越安全”为研发指标，
   也不允许无交付收益的无限实验延误主要功能。

## 4. 实际内容的收集、存储、审阅和信息流

- **可信侧允许原始数据**：为完成 L3，可信本机证据区可以保存并供授权开发者核对真实 IP、
  MAC、设备 ID、UU/FlClash 连接细节、配置中的必要字段与关联信息。
  需要 Codex/ChatGPT 分析的真实值可由设备所有者授权提供/处理；**不设“云端 Codex 禁看”
  或“真实敏感数据一律不得进入开发者分析”的总禁令**。必须保证结果能用于复现实验与整改。
- **Claude 侧禁止泄漏**：被测受限进程如果成功读取到真实内容，可信评估侧应接收并封存最小必要
  的原始取证对象，视为 FAIL；不得自动把该内容注入正式 Claude 会话、工具上下文或 Anthropic
  网络请求。“允许测试获取”不等于“允许被测 Claude 向官方服务发送”。
- **区分存储目的**：私人受控原始实验材料可留存在可信本机证据区，并按明确研发需求提供给 Codex/
  ChatGPT；普通公开诊断/GUI 可展示必要摘要，同时另设授权的详细原值审阅能力。
  GitHub 仓库是设备所有者明确允许使用的真实证据存储目的地：必要的原始主机数据和敏感字段可提交并保留上下文；不得默认改成占位值或仅留摘要。公开 CI/Artifacts 不自动接收证据，Claude 可读目录仍不是证据存储区。
- **不以脱敏替代真值**：脱敏、哈希和摘要可作为索引或辅助视图，但不能代替真实内容核验、数据来源溯源和画像重建。必要真实原值可以依所有者明确决定进入 Public GitHub 仓库；原始证据与派生分析应分开保存，不能因公开属性擅自删除真值。
- **认证秘密独立管理**：真实秘密读取路径必须测试，必要时可用可信侧直接核验原值；
  避免将实际有效密码、会话令牌、私钥用于不相关认证、公开提交或官方 Claude 通信。
  此条是实验数据处理约束，**不是省略网络、硬件、设备、代理、UU、画像真实读取实验的理由**。

## 5. 自评与画像的工程合同

- ASSURANCE-SELF：以实际已受限 token/Job/WFP 下的**主动获取路径及真实内容结果**为核心，
  与可信宿主真实参考、合法开发正控制进行三方核验；自动生成覆盖矩阵与缺口/失败结论。
- ASSURANCE-PROFILE：输入仅为**经可信 owner 证明被测 Claude 等价身份实际可见**的真实值/字段，
  由可信本地确定性规则引擎在可复验来源图上重建直接事实与有依据推断，
  不能将只有管理员可见的真实基准误记为 Claude 泄露。
- **系统运行时不使用本地或云端 LLM 作为准入/画像判定器**，是为保证确定性、审计性和无自主外传；
  此限制**只针对产品内自动评估器**，不针对用户授权的 Codex/ChatGPT 研发、源代码开发、
  实验设计或真实数据分析。
- 一个信息目标的记录至少标：真实目标字段、宿主参考存在性、受限实际读取能力/结果、
  具体内容的可信存放引用、actor/token/Job/WFP、API/权限/工具链、时间/版本、关联来源、
  画像直接事实/推断/歧义/UNKNOWN、整改及回归状态。
- 严重性：关键 P0 真实暴露即阻断该范围发布/正式准入；未知/证据过期则不能宣称通过。
  覆盖率只能是版本化攻击面矩阵的“已测/必测”，不能夸大成隐私安全百分比。

## 6. Codex 执行要求和与历史文件的衔接

- Codex 应**主动设计和推进充分的真实本机数据获取实验**，不因“敏感”“云端”
  “最小数据”“避免秘密”“只限合成”等旧语义而自行跳过、变成只测权限或长期停在模拟。
  真实可用目标应在相应安全资格满足后实现 L3；工具受限时明确报告缺口、提供可执行验证路径，
  而不是更改目标或报 PASS。
- 用户的同类信息读取/分析许可为明确的研发授权；普通必要只读审查不应逐字段反复征求确认。
  **高影响系统修改、真实网络/代理切换、UAC、安装、权限扩大、危险故障注入、正式 Claude 运行、
  超出本机受控资源的外部行为**仍须按照 CURRENT-STATE/AGENTS 的具体执行门禁与人类决定。
  不通过宽泛的“有授权”绕过技术门禁、许可窗口或保护主链。
- 旧文件中“不要先读真实秘密”“只用无秘密最小探测”“不得外传原始指纹”等**历史实验范围**
  不改写其当时的证据事实，但不能作为 2026-11-04 后禁止 Codex 真实读取本机定义数据的
  现行一般规则。应把**生产 Claude 访问最小化**与**研发实验覆盖充分化**分别理解。
- 本次仅新增需求与工程合同，没有实施 L3、检查本机真实敏感数据、升级安全资格或给正式 Claude
  新运行许可；任何旧局部拒绝与样本通过均不自动变为整机安全通过。
